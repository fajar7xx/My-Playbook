Fresh Install → Laravel Deployment di AWS Lightsail

Target: Ubuntu 24.04 LTS, PHP 8.4 hanya dari Ondřej PHP PPA, Nginx official stable dari nginx.org, database fleksibel, Redis, Horizon, Telescope, dan staging via http://IP_PUBLIC:8000.

✅ No php.new ✅ Ondřej PHP only ✅ Nginx stable official ✅ MySQL/MariaDB/Postgres/MongoDB/SQL Server ✅ Redis + Horizon + Telescope ✅ Reusable PROJECT_NAME
Dokumentasi ini sengaja memakai variabel PROJECT_NAME, PROJECT_PATH, dan PUBLIC_IP. Jadi saat setup project baru, kamu wajib menentukan nama project terlebih dahulu, bukan mengandalkan contoh nama tertentu.

1. Tentukan Nama Project Dulu

Setiap setup project dimulai dari deklarasi nama project. Contoh di bawah bisa diganti untuk project apa pun.

Project variables — wajib dicek sebelum lanjut
# GANTI SESUAI PROJECT KAMU
export PROJECT_NAME="nama_project_kamu"
export PROJECT_REPO="git@github.com:username/repository.git"
export PROJECT_BRANCH="main"
export PROJECT_BASE="/var/www"
export PROJECT_PATH="${PROJECT_BASE}/${PROJECT_NAME}"
export PUBLIC_IP="YOUR_LIGHTSAIL_PUBLIC_IP"
export APP_PORT="8000"
export PHP_VERSION="8.4"

# Database default; boleh diganti sesuai opsi database
export DB_CONNECTION="mysql"
export DB_NAME="${PROJECT_NAME}_db"
export DB_USER="${PROJECT_NAME}_user"
export DB_PASSWORD="CHANGE_THIS_STRONG_PASSWORD"

echo "Project name : ${PROJECT_NAME}"
echo "Project path : ${PROJECT_PATH}"
echo "App URL      : http://${PUBLIC_IP}:${APP_PORT}"
Jangan lanjut kalau PROJECT_NAME masih kosong atau masih contoh. Semua file Nginx, database user, deploy script, Supervisor, dan log akan memakai nama ini.

4. Install Nginx Terbaru Stable dari nginx.org

Ini memakai repository official stable dari nginx.org, bukan package default Ubuntu.

Remove Nginx bawaan jika sudah ada
sudo systemctl stop nginx || true
sudo apt remove -y nginx nginx-common nginx-core || true
sudo apt autoremove -y
Setup Nginx official stable repo
sudo apt install -y curl gnupg2 ca-certificates lsb-release ubuntu-keyring

curl https://nginx.org/keys/nginx_signing.key | gpg --dearmor \
  | sudo tee /usr/share/keyrings/nginx-archive-keyring.gpg >/dev/null

gpg --dry-run --quiet --no-keyring --import --import-options import-show \
  /usr/share/keyrings/nginx-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] https://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" \
  | sudo tee /etc/apt/sources.list.d/nginx.list

echo -e "Package: *\nPin: origin nginx.org\nPin: release o=nginx\nPin-Priority: 900\n" \
  | sudo tee /etc/apt/preferences.d/99nginx

sudo apt update
sudo apt install -y nginx

sudo systemctl enable nginx
sudo systemctl start nginx
nginx -v
sudo systemctl status nginx
Official nginx docs menyediakan repository stable untuk Ubuntu 24.04 “noble” dan instruksi repo pinning agar package nginx.org diprioritaskan dibanding package distribusi.

7.2 PHP-FPM pool tuning untuk Lightsail kecil

Edit FPM pool
sudo nano /etc/php/8.4/fpm/pool.d/www.conf
Recommended www.conf
user = www-data
group = www-data
listen = /run/php/php8.4-fpm.sock
listen.owner = www-data
listen.group = www-data
listen.mode = 0660

pm = dynamic
pm.max_children = 8
pm.start_servers = 2
pm.min_spare_servers = 1
pm.max_spare_servers = 3
pm.max_requests = 500

request_terminate_timeout = 120s
catch_workers_output = yes
Restart PHP-FPM
sudo systemctl restart php8.4-fpm
sudo systemctl status php8.4-fpm
Jika opcache.validate_timestamps=0, setiap deploy harus restart PHP-FPM agar file PHP terbaru kebaca.

8. Node.js via NVM + npm/pnpm

Untuk Laravel/Vite, install Node.js lewat NVM agar versi Node bisa dikontrol per server/project. Package manager bisa pilih salah satu: npm bawaan Node, atau pnpm untuk install lebih cepat dan hemat disk.

Rekomendasi default: pakai nvm install --lts, lalu gunakan package manager sesuai lockfile project: package-lock.json → npm, pnpm-lock.yaml → pnpm.

export NVM_DIR="$HOME/.nvm"

[ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"

Pakai ini kalau project punya package-lock.json atau kamu ingin setup paling standar.

8.5 Pilihan B — pakai pnpm

Pakai ini kalau project punya pnpm-lock.yaml atau kamu ingin install dependency lebih cepat dan efisien.

Enable pnpm via Corepack
# Node modern menyertakan Corepack, tapi bisa perlu di-enable
corepack enable

# Aktifkan pnpm terbaru yang stabil menurut Corepack
corepack prepare pnpm@latest --activate

pnpm -v
Install/build dengan pnpm
cd "${PROJECT_PATH}"

nvm use

# Jika package.json punya packageManager, Corepack akan mengikuti versi itu.
pnpm install --frozen-lockfile

# Jika belum ada pnpm-lock.yaml, gunakan:
# pnpm install

pnpm run build

8.6 Auto-detect npm atau pnpm saat deploy

Reusable asset build snippet
cd "${PROJECT_PATH}"

export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"

if [ -f ".nvmrc" ]; then
  nvm install
  nvm use
else
  nvm install --lts
  nvm use --lts
fi

if [ -f "pnpm-lock.yaml" ]; then
  corepack enable
  corepack prepare pnpm@latest --activate
  pnpm install --frozen-lockfile
  pnpm run build
elif [ -f "package-lock.json" ]; then
  npm ci
  npm run build
else
  npm install
  npm run build
fi
Jangan install Node dari apt install nodejs npm jika dokumentasi ini memakai NVM. Campuran apt Node + NVM sering bikin versi Node/NPM berbeda antara SSH session dan deploy script.

12. Folder Permission yang Bisa Jalan

Production-like permission fix
cd "${PROJECT_PATH}"

sudo mkdir -p storage/app/public \
storage/framework/cache/data \
storage/framework/sessions \
storage/framework/views \
storage/logs \
bootstrap/cache

sudo touch storage/logs/laravel.log

# Owner codebase: deploy user + web group
sudo chown -R ubuntu:www-data "${PROJECT_PATH}"

# Default safe permissions
sudo find "${PROJECT_PATH}" -type d -exec chmod 755 {} \;
sudo find "${PROJECT_PATH}" -type f -exec chmod 644 {} \;

# Writable Laravel runtime folders
sudo chmod -R ug+rwx storage bootstrap/cache
sudo find storage bootstrap/cache -type d -exec chmod 2775 {} \;
sudo find storage bootstrap/cache -type f -exec chmod 664 {} \;

# Optional ACL agar ubuntu dan www-data sama-sama bisa write runtime folders
sudo setfacl -R -m u:ubuntu:rwx -m u:www-data:rwx storage bootstrap/cache
sudo setfacl -dR -m u:ubuntu:rwx -m u:www-data:rwx storage bootstrap/cache

sudo usermod -aG www-data ubuntu

php artisan optimize:clear
php artisan storage:link
Setelah usermod, logout SSH lalu login ulang agar group www-data aktif untuk user ubuntu.

Create deploy.sh

git fetch origin

composer install --no-dev --optimize-autoloader

export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"

if [ -f ".nvmrc" ]; then
  nvm install
  nvm use
else
  nvm install --lts
  nvm use --lts
fi

if [ -f "pnpm-lock.yaml" ]; then
  corepack enable
  corepack prepare pnpm@latest --activate
  pnpm install --frozen-lockfile
  pnpm run build
elif [ -f "package-lock.json" ]; then
  npm ci
  npm run build
else
  npm install
  npm run build
fi

php artisan migrate --force

php artisan optimize:clear
php artisan config:cache
php artisan route:cache || true
php artisan view:cache
php artisan event:cache || true

sudo chown -R ubuntu:www-data "${PROJECT_PATH}"

sudo systemctl reload nginx

sudo supervisorctl reread || true
sudo supervisorctl update || true
sudo supervisorctl restart "${PROJECT_NAME}-horizon:"* || true
sudo supervisorctl restart "${PROJECT_NAME}-worker:"* || true

php artisan up

echo "Deployment completed: ${PROJECT_NAME}"
EOF

chmod +x "${PROJECT_PATH}/deploy.sh"

19. Troubleshooting

Permission denied laravel.log / bootstrap cache

Fix Laravel writable dirs
cd "${PROJECT_PATH}"

sudo mkdir -p storage/logs bootstrap/cache storage/framework/cache/data storage/framework/sessions storage/framework/views
sudo touch storage/logs/laravel.log

sudo chown -R ubuntu:www-data "${PROJECT_PATH}"
sudo chmod -R ug+rwx storage bootstrap/cache
sudo find storage bootstrap/cache -type d -exec chmod 2775 {} \;
sudo find storage bootstrap/cache -type f -exec chmod 664 {} \;

php artisan optimize:clear

502 Bad Gateway

Check PHP-FPM socket
sudo systemctl status php8.4-fpm
ls -la /run/php
sudo nginx -t
sudo tail -f /var/log/nginx/${PROJECT_NAME}_error.log

Port 8000 tidak bisa dibuka

Debug port
sudo ss -tulpn | grep :8000
sudo ufw status
sudo nginx -t
sudo systemctl reload nginx

Pastikan juga Lightsail Networking → IPv4 Firewall punya custom TCP rule port 8000.

Composer gagal buat vendor

Fix composer ownership
sudo chown -R ubuntu:ubuntu "${PROJECT_PATH}"
cd "${PROJECT_PATH}"
composer install

Route cache error karena closure

Fallback cache commands
php artisan optimize:clear
php artisan config:cache
php artisan view:cache
php artisan event:cache || true
